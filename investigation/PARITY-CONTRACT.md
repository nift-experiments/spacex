# Public-output parity contract

Both maintained-source variants target the same captured production output. No redesign, simplified media or weaker agent parity.

Reconcile navigation/lazy routing/CMS-linked route candidates, HTTP status and redirects, page family, metadata and captured asset hashes. Fixture browser viewports: 1440×1000, 768×1000, 390×844 and 320×844, plus observable responsive breakpoints. Compare real homepage, vehicle/product, mission/media, information/forms and mobile menu states before family-wide scaling.

Compare screenshot/geometry, scroll transitions, hover/focus, keyboard menus, text/links, video autoplay/muted/loop/poster/cropping/lazy loading/failure states and reduced motion. Exact RGB is suitable only for settled deterministic states; moving video/animation requires timing/geometry and media-contract checks rather than invented pixel equality. Preserve and disclose every difference.

No analytics, telemetry, real form submissions or production mutations. External links are inspected without purchase/account flows. Private-backend-dependent functionality retains its UI/service boundary and is disclosed; deterministic local fixtures do not certify the private production backend.

A complete reference freeze precedes content migration. Shared shell/media/navigation/section/path proof is time-boxed; it must lead directly to corpus-wide generation, not a handful of indefinitely polished pages. The first usable migrated checkpoint includes the real homepage and a deep route.

Lifecycle gate: one-page/shared/nav/CSS/JS/media-metadata edits and route add/rename/delete; incremental-vs-forced output equivalence and retired outputs. Profile only after parity, then revalidate and run five serialized samples per final scenario for both models. Fresh application state differs from cold OS caches. RSS accompanies every published incremental scenario. No fabricated upstream build comparison.
